## 1. Публичные экраны

### P1. Вход `/login`
Макет: как hero эталона, двухколоночный. Левая колонка: kicker `Доступ`, H1 «Войти в цифровой отдел маркетинга», форма. Правая: панель с «терминальным» описанием (`Session // Standby`, три строки о ценности портала на `LinedBlock`).
- Поля: email, пароль (показать/скрыть). Ссылки: «Забыли пароль», «Регистрация».
- Действия: войти (Primary). Ошибки: неверные данные (единый текст, без раскрытия, существует ли email), rate-limit (сообщение с таймером).
- Редиректы после входа: нет `Enrollment ACTIVE` → `/pay`; не заполнен бизнес-профиль → `/onboarding`; иначе `/` (или `callbackUrl`). ADMIN/EDITOR → `/admin`.

### P2. Регистрация `/register`
- Поля: имя, email, телефон (опционально), пароль (мин. 10 символов, индикатор), **чекбокс согласия на обработку ПДн** (обязателен, ссылка на `/legal/privacy`) и принятие оферты.
- Действие: создать аккаунт → письмо подтверждения email (ссылка, TTL 24 ч) → сразу редирект на `/pay`. Доступ к контенту только после оплаты.
- Приглашение: поддержать `?invite=code` (опционально, ручная выдача тарифа админом, см. A2).

### P3. Восстановление пароля
Форма email → письмо со ссылкой → форма нового пароля. Одинаковый ответ для существующих/несуществующих email.

### P4. Тариф и оплата `/pay`
- Три `Panel`-карточки тарифов (SELF / SUPPORT / VIP). SUPPORT помечен StatusPill «Целевой». В каждой: цена (`font-mono`), название, список включённого (features list: активные иконки для включённого, неактивные для недоступного, по матрице из `05`), Primary «Оплатить».
- Режим **апгрейда** (у пользователя уже есть Enrollment): текущий тариф помечен, у старших тарифов показана цена доплаты («Доплата 100 000 ₽»), у младших кнопка неактивна.
- Действие: `POST /api/payments` → редирект на `confirmationUrl` провайдера. Возврат на `/pay/result?paymentId=…`.
- Состояния: провайдер недоступен (ошибка с повтором), уже оплачено (редирект на `/`).

### P5. Результат оплаты `/pay/result`
Опрашивает статус платежа (polling 2 с, до 60 с). Состояния: `PENDING` (моно-текст «Ожидаем подтверждение…» + пульс), `SUCCEEDED` (панель «Доступ открыт» + Primary «Перейти к онбордингу»), `CANCELED/FAILED` (причина + «Повторить оплату»). Доступ открывается только webhook’ом; страница лишь показывает статус.

### P6. Юридические документы `/legal/privacy`, `/legal/offer`
Рендер `LegalDocument` последней версии. Текст в `LinedBlock`-стиле не нужен, обычная типографика.

## 2. Онбординг

### S0. Бизнес-профиль `/onboarding`
Пошаговая форма (4 шага, сегментированный прогресс-бар из квадратов) внутри одной панели:

1. **Кто ты**: имя, компания, ниша, сайт/соцсети, «расскажи о себе как о собственнике».
2. **Продукт**: что продаёшь, средний чек, ключевые услуги.
3. **Клиент**: кто покупает, где ищет, какие боли.
4. **Голос бренда**: тон, слова-маркеры, чего избегать, 1–3 примера текстов (textarea).

Дополнительно (шаг 1 или 4): ориентир по выручке (диапазон, необязательно), цель курса.
- Автосохранение черновика; завершение = `POST /api/profile/business`; после завершения экран «Профиль собран» с кнопкой «Скопировать бизнес-профиль для агента» (собирает markdown-блок для загрузки агентом в память: используется на Дне 1 маршрута).
- Профиль можно редактировать позже в `/profile`.
- Пропуск запрещён (без профиля редирект сюда), кроме ролей ADMIN/EDITOR.

## 3. Студенческая зона

### S1. Главная `/`
Hero-блок в стиле эталона + рабочие секции:

1. **Приветствие**: kicker `Кабинет`, H1 «{Имя}, собираем твой отдел маркетинга», подсказка «Следующий шаг» (Primary): ведёт на первый невыполненный шаг маршрута или на рекомендацию куратора.
2. **Карусель-баннеры** (`Banner`): анонсы эфиров, новые кейсы. Ручной свайп/стрелки, автопрокрутка 6 с, пауза при hover. Оформление: панель с уголками, счётчик `01 / 04` моно.
3. **Плитка разделов**: 6 панелей (Маршрут, Скиллы, Юзкейсы, Уроки, Эфиры, Лидерборд), иконка Solar + описание + счётчик доступного (например «12 / 30 скиллов»). Закрытые разделы с замком.
4. **Виджет прогресса**: сегментированные квадраты по блокам маркетинга (Стратегия / Трафик / Контент / Удержание и деньги / Инфра агента), в каждой группе N внедрено из M. Внизу поле **«Движение по деньгам»**: сумма за период + кнопка «Добавить запись» (модалка `MoneyEntry`). Общая сумма моно-шрифтом.
5. **Лента «Новое»**: последние опубликованные юниты/скиллы (по 5), с тегом типа и датой. Клик ведёт в карточку.
6. **Ближайший эфир** (если есть `airedAt` в будущем): дата, тема, ссылка на Zoom (поле в настройках, см. A12), напоминание в Telegram.
7. **Карточка куратора** (SUPPORT+): последний разбор и «1–2 следующих шага» (см. S13). Для SELF: замок и CTA на апгрейд.

Состояния: новый пользователь без активности (пустые состояния с CTA «Начать маршрут»).

### S2. Маршрут «Твой маркетинговый агент за 3 дня» `/route`, `/route/[day]`
**Спина портала.** Все тарифы.
- `/route`: hero (kicker `Маршрут`, H1 «Твой маркетинговый агент за 3 дня»), три панели-«дня» в ряд (на мобильном стеком), у каждой: номер дня, название, итог-артефакт («Агент, который знает твой бизнес»), прогресс (N из M шагов), статус-пилл (Не начат / В работе / Готов). Общий прогресс сверху.
- `/route/[day]`: список шагов (чек-лист):
  - Шаг = строка `features list`-стиля (выполненный: акцентная иконка `solar:check-circle-linear`, невыполненный: `zinc-400`). Клик раскрывает шаг (accordion в стиле панели).
  - В раскрытом шаге: описание, **блоки «Команда/Промпт»** (`LinedBlock`, mono, кнопка «Скопировать» с тостом «Скопировано»), при наличии `linkedSkill` карточка-ссылка на скилл и кнопка «Отправить агенту».
  - **Фиксация артефакта:** чекбокс «Сделал» + поле «Что получилось» (текст/ссылка, `artifactNote`/`artifactUrl`), обязательное, если `artifactRequired`. Отметка ставит `done`, время, пересчёт очков.
  - Снять отметку можно.
  - Навигация «Предыдущий день / Следующий день».
- Содержание по ТЗ:
  - **День 1: Фундамент.** Окружение (Claude Code), личность агента, загрузка бизнеса в память. Артефакт: «Агент, который знает твой бизнес». Шаг про бизнес-профиль показывает кнопку «Скопировать бизнес-профиль» (из S0).
  - **День 2: Первая боевая работа.** Подключение 2–3 маркетинг-скиллов (аудит + позиционирование/контент-движок). Артефакт: «Агент делает маркетинг, а не болтает».
  - **День 3: Агент в кармане + автоматизация.** Вывод в Telegram, память между сессиями, первый крон. Артефакт: «Маркетинговый агент 24/7 в мессенджере». Шаг Telegram включает подсказку по привязке аккаунта (см. S12, вкладка «Telegram») и по созданию бота у студента; платформа ключи не хранит.
- Гейтинг: доступен всем активным тарифам. Закрытый Enrollment (`EXPIRED`) видит read-only.
- Завершение 3-го дня показывает панель «Маршрут пройден», предлагает следующий шаг (библиотека скиллов / уроки) и поднимает событие для лидерборда.

### S3. Скиллы: библиотека `/skills`
- Hero-заголовок, поиск (по названию, описанию, тегам; debounce 250 мс, серверный поиск через `ILIKE`/`pg_trgm`).
- **Группировка по маркетинговой функции:** 5 секций с заголовками: Стратегия · Трафик · Контент · Удержание и деньги · Инфра агента. Быстрые якоря-табы сверху (моно-табы).
- Фильтры: теги (мультивыбор `Tag`-чипы), «Только доступные мне», «Внедрено / Не начато» (по `Progress`).
- Карточка в списке (`Panel`): название, `shortDesc` (2 строки), время освоения (`solar:clock-circle-linear`), теги, статус студента (StatusPill: `Внедрён` и т.д.), замок при недоступности (показывается превью без промпта и файла).
- Пустой результат: `LinedBlock` «Ничего не найдено» + сброс фильтров.
- URL хранит фильтры (`?q=&tags=&group=`).

### S4. Скилл: карточка `/skills/[slug]`
Двухколоночный layout.
- Левая: kicker (группа), H1, теги, блоки «Что делает», «Что на входе», «Что на выходе», «Время освоения» (панели-«спецификации» с микро-лейблами `INPUT // OUTPUT`).
- Правая: **Demo на реальном кейсе** (Kinescope-плеер или ссылка на юзкейс из `demoUnit`); ниже панель действий:
  - Primary/Action **«Отправить агенту»**: раскрывает `LinedBlock` с полным промптом и копирует его в буфер (тост). Ставит `VIEWED` при первом использовании.
  - «Скачать файл скилла» (presigned URL, имя `fileName`).
  - Блок «Мой статус»: выбор `Сдал / Внедрил / Результат` (по правилам `03`, с полем «Что сделал»).
- Внизу: «Связанные скиллы» (тот же тег, до 3), «Где применяется» (шаги маршрута, юзкейсы с этим скиллом в demo).
- Гейтинг: без доступа видны заголовок, описание, вход/выход, время; промпт, файл, demo скрыты, панель замка с CTA апгрейда (`/pay?upgrade=SUPPORT`).

### S5. Уроки `/lessons`
- Hero + общий прогресс по программе (просмотрено N из ~90–100 видео).
- **10 блоков** как аккордеоны/панели: заголовок блока, метод/принцип, число уроков (8–10), прогресс блока, список уроков (номер, название, длительность, статус, тег «отправить агенту» если есть промпт).
- Привязка к маршруту: у блока метка «День 1» / «День 2» и т.п., если `routeDayId` задан.
- Фильтр: «Не просмотрено», поиск по названию.

### S6. Урок `/lessons/[slug]`
Рендерит `<ContentUnit type=LESSON>`:
1. Kicker «Блок N», H1, тег принципа метода, время.
2. **Видео-плеер Kinescope** (16:9, в панели с уголками).
3. **Кликабельные таймкоды** рядом с плеером (список `mm:ss — подпись`; клик = seek, активный подсвечивается по `timeupdate`).
4. **Промпт-блок** (если задан): `LinedBlock` + «Отправить агенту» + «Скопировать».
5. Прогресс: автоматически `VIEWED` при ≥ 80% просмотра; кнопки «Сдал», «Внедрил» (по правилам `03`).
6. Навигация: «Предыдущий / Следующий урок» внутри блока, «К блоку».
- Гейтинг по `minPlan` (по матрице все уроки на всех тарифах, но поле есть).

### S7. Юзкейсы `/usecases`
- Hero + фильтры по тегам и клиенту-кейсу (Клиника Ешидоржиева, Маамуу, Сайн, Мир унтов, Barguzin и др., из `caseClient`), поиск.
- Сетка карточек: обложка (по стилю с grayscale), название, клиент, 2–3 ключевых KPI (`font-mono`, например «≥ 82/100»), теги, время освоения, статус студента.
- Сортировка: новые / по прогрессу.

### S8. Юзкейс `/usecases/[slug]` (эталон анатомии контент-юнита)
Каркас строго по ТЗ 5.6:
1. Заголовок + теги + время освоения.
2. Видео-плеер.
3. **Три таба: Обзор / Статья / Полный транскрипт.**
4. Кликабельные таймкоды (рядом с плеером во всех табах).
5. Таб **Обзор**:
   - блок **ЦЕЛЬ** (`goal`);
   - блок **РЕЗУЛЬТАТ** (`result`) с **KPI-плитками** (`kpis[]`: значение крупно моно-шрифтом, подпись, подсказка). Пример: «Статья ≥ 82/100», «Доскролл 75%», «IndexNow», «3 слоя SEO/AEO/GEO»;
   - блок **ОПИСАНИЕ**: rich-text + ссылки на открытый репозиторий (`repoLinks[]` как кнопки с иконкой `solar:link-linear`);
   - **«Отправить агенту» + блок ПРОМПТ** (многошаговый, стопы на согласование владельца выделены маркером `⏸ СТОП: согласуй с владельцем` внутри `LinedBlock`) + «Скопировать»;
   - **ПОШАГОВЫЕ ДЕЙСТВИЯ**: нумерованный список (моно-номер `01`, `02`…), у каждого шага заголовок, текст и блок **КОМАНДА** с копированием.
6. Таб **Статья**: рендер `article` (rich-text), оглавление по заголовкам справа на десктопе.
7. Таб **Полный транскрипт**: `transcript` в `LinedBlock`; поиск по тексту (Ctrl+F внутри таба) и клик по метке времени в тексте `[12:35]` = seek.
8. Панель статуса студента: `Просмотрел / Сдал / Внедрил / Результат` + поле «что сделал» + добавление `MoneyEntry` для статуса «Результат».
9. «Связанные скиллы» (по тегам и `demoUnitId`).
- Deep-link: `?tab=article&t=125` открывает таб и перематывает видео.

### S9. Эфиры `/streams`
- Архив записей еженедельных Zoom-разборов, сортировка по `airedAt` desc. Карточка как у юзкейса: обложка, дата, название, теги, длительность, статус.
- Блок «Ближайший эфир» вверху (SUPPORT+ ссылка на Zoom, SELF: замок).
- Гейтинг: SELF видит **частично** (доступны юниты с `partialFreePreview=true`; политика «частично» финализируется с Жаргалом, по умолчанию: последние 2 эфира полностью, остальные превью).

### S10. Эфир `/streams/[slug]`
Тот же `<ContentUnit type=STREAM>`: видео + табы (Обзор / Статья / Транскрипт) + таймкоды + промпт-блок (если есть). Отличие: показывает дату эфира и «Разбор кейса участника» в Обзоре.

### S11. Лидерборд `/leaderboard`
- Шкала-легенда: **Посмотрел = 1 · Сдал = 2 · Внедрил = 5 · Результат в деньгах = 10** (панель с четырьмя моно-ячейками).
- Таблица топа потока: место, аватар, имя, очки, разбивка (viewed/submitted/implemented/result счётчики), сумма «результата в деньгах» (только у тех, кто дал согласие показывать деньги, иначе «·····»), прогресс по 5 группам (мини-сегменты).
- Своя строка закреплена/подсвечена акцентной границей; если пользователь вне топ-10, показывается «Ты на N месте, до X места {Δ} очков».
- Фильтры: «Мой поток / Все».
- Приватность: в профиле переключатель `showInLeaderboard` (скрыт = не виден другим; себя видит). «Мотиватор, не позор»: не показывать последних, показывать топ-10 + себя. Тексты нейтральные.
- Обновление: подгрузка при заходе + revalidate 60 с.

### S12. Профиль / Кабинет `/profile`
Табы (моно-табы):

1. **Профиль:** имя, email, телефон, аватар (загрузка в S3), смена пароля.
2. **Бизнес-профиль:** редактирование данных онбординга, кнопка «Скопировать для агента».
3. **Прогресс:** таблица всех единиц (юниты + скиллы) со статусом, датой, ссылкой на `proofNote`; сумма очков; журнал «Движение по деньгам» (CRUD `MoneyEntry`, итог).
4. **Тариф и оплата:** текущий тариф, дата активации, история платежей (дата, сумма, статус), кнопка «Улучшить тариф» (→ `/pay` в режиме апгрейда), таблица «Что открыто/закрыто» (по матрице).
5. **Telegram:** привязка: кнопка «Привязать» генерирует одноразовый код/deeplink `t.me/{bot}?start=<token>`, статус «Привязан @username», отключение. Настройки уведомлений (email/Telegram по типам).
6. **Приватность:** согласия (дата и версия), показывать в лидерборде, запрос на удаление аккаунта и выгрузку данных.

### S13. Разбор куратора `/profile/curator`
Доступно на SUPPORT и VIP.
- Список карточек `CuratorNote` по неделям (последняя развёрнута).
- Карточка: «Что внедрено на неделе» (краткий итог), «Принцип метода» (тег вроде `сегментация ABCDX`, `лестница Ханта`, `воронка`), **1–2 следующих шага** (заголовок, зачем, кнопка-ссылка на урок/скилл/шаг маршрута). Оформление: Panel `Curator // Weekly`, `LinedBlock`.
- Форма **«Что сделал за неделю»** (необязательное поле, `WeeklyReport`), редактируемая до момента запуска джобы недели; подсказка, что куратор учитывает её.
- Отметка прочтения, кнопка «Отправить куратору вопрос» **не** делаем (вне scope).
- Для SELF: замок и CTA апгрейда.

### S14. Уведомления
Иконка-колокол в nav с индикатором `bg-[#d95321]` квадратом. Выпадающая панель (последние 10) и страница `/profile/notifications`. Типы: новый разбор куратора, новый контент, напоминание об эфире, изменение статуса оплаты. Дублируются в Telegram/email по настройкам.

## 4. Админка (роли ADMIN, EDITOR)

Общий layout: тот же frame; левое моно-меню (на мобильном выпадающее): **Обзор · Студенты · Оплаты · Тарифы · Скиллы · Маршрут · Контент · Теги · Баннеры · Поток · Куратор · Пользователи · Настройки**. EDITOR видит только Скиллы, Маршрут, Контент, Теги, Баннеры. Kicker всех страниц: `Admin`.

### A1. Обзор `/admin`
Плитки метрик (моно-числа): студентов всего/активных, оплат за 30 дней, выручка, новых регистраций, платежей в ожидании. Списки: последние регистрации, последние платежи, контент-черновики (для EDITOR). Быстрые действия: «Новый скилл», «Новый юнит».

### A2. Студенты `/admin/students`, `/admin/students/[id]`
- Таблица: имя, email, тариф, статус оплаты, поток, очки, дата регистрации. Поиск, фильтр по тарифу/статусу/потоку, сортировка, экспорт CSV. Пагинация серверная.
- Карточка студента: профиль, бизнес-профиль (только чтение), прогресс по юнитам и скиллам с `proofNote`, `MoneyEntry`, история платежей, заметки куратора и `WeeklyReport`, действия (ADMIN): **выдать/сменить тариф вручную** (с обязательной причиной, пишется `AuditLog`), продлить/закрыть доступ, сбросить пароль (письмо), назначить поток, войти «как студент» (impersonation, read-only режим с баннером и аудитом), скрыть из лидерборда, анонимизировать.
- Создание приглашения/ручное добавление студента (email + тариф) → письмо со ссылкой для пароля.

### A3. Оплаты и тарифы
- `/admin/payments`: таблица платежей, фильтры по статусу/периоду/провайдеру, детали (raw webhook), ручная пометка «оплачено вне платформы» (создаёт Enrollment, `grantedByAdmin`), возврат помечается статусом (сам возврат делается в кабинете провайдера).
- `/admin/plans`: редактирование цены, названия, списка features, активности. Изменение цен не влияет на прошедшие платежи.

### A4. Скиллы `/admin/skills`, `/admin/skills/[id]`
- Список: поиск, фильтр по группе/тегу/статусу/`minPlan`, drag-сортировка внутри группы, массовые действия (опубликовать, архивировать).
- **Форма создания/редактирования карточки:** название, slug, группа, «что делает», вход, выход, время освоения, теги (мультивыбор с созданием на лету), demo (выбор юзкейса или Kinescope-id), **промпт** (моноспейс-редактор с предпросмотром на `LinedBlock`), **файл скилла** (загрузка в S3, замена, удаление), **гейт-уровень** (`minPlan`: SELF = «базовый набор», SUPPORT), статус (черновик/опубликован), предпросмотр «как студент на тарифе X» (переключатель).
- Валидация zod, автосохранение черновика, история изменений не требуется.

### A5. Маршрут `/admin/route`
Редактор 3 дней и шагов: заголовок, итог-артефакт, шаги (drag-сортировка), для шага: заголовок, описание (rich-text), список команд/промптов (тип, подпись, текст), обязательность артефакта, подсказка артефакта, привязанный скилл.

### A6. Контент-юниты `/admin/content` (единая форма)
- Список с табами типа (Все · Уроки · Юзкейсы · Эфиры), фильтры (блок, тег, статус, клиент), поиск, сортировка, drag-порядок.
- **Единая форма** `/admin/content/new?type=LESSON|USECASE|STREAM` и `/admin/content/[id]`. Секции формы отображаются по типу:
  - **Общее:** тип, название, slug, краткое описание, обложка, теги, время освоения, `minPlan`, статус, дата публикации, «частичный доступ».
  - **Видео:** Kinescope ID (валидация, проверка доступности по API), длительность, **редактор таймкодов** (строки `mm:ss` + подпись, добавление «с текущей позиции плеера» в предпросмотре).
  - **Промпт-блок:** текст промпта, заметка.
  - **LESSON:** блок 1–10, порядок в блоке, привязка к дню маршрута, принцип метода.
  - **USECASE:** клиент-кейс, ЦЕЛЬ, РЕЗУЛЬТАТ, **KPI-редактор** (метка, значение, подсказка), ОПИСАНИЕ (TipTap), ссылки на репо, Статья (TipTap), Транскрипт (textarea с автопарсингом меток времени), **шаги** (список: заголовок, текст, команда; drag-сортировка).
  - **STREAM:** дата эфира, ссылка на Zoom (опц.).
- Предпросмотр «как увидит студент» (правая панель/отдельная вкладка) через тот же `<ContentUnit />`.
- Публикация создаёт `Notification` типа `NEW_CONTENT` (опция чекбокс «Уведомить студентов») и попадает в ленту «Новое».
- Дублирование юнита, архивирование.

### A7. Теги `/admin/tags`
CRUD, слияние тегов, счётчик использования.

### A8. Баннеры `/admin/banners`
CRUD карусели Главной: заголовок, подзаголовок, картинка, ссылка, период показа, порядок.

### A9. Дашборд потока `/admin/cohort`
- Выбор потока. Таблица прогресса **по студентам**: колонки Посмотрел / Сдал / Внедрил / Результат (счётчики и мини-бары), очки, движение по деньгам, тариф, последняя активность (дата), маршрут (X/Y шагов). Фильтр по тарифу, сортировка, поиск, экспорт CSV.
- Сводка сверху: воронка по потоку (сколько студентов дошло до каждой стадии), средние очки, число «застрявших» (нет активности > 7 дней).
- Тепловая матрица «студент × группа скиллов» (5 колонок, заливка квадратов по статусу, в стиле сегментов).
- Клик по студенту → A2 карточка.

### A10. Куратор `/admin/curator`
Переключатель `CURATOR_ENABLED`, расписание (день/час, по умолчанию пн 09:00 МСК), ручной запуск для студента/всех, список последних запусков со статусом и токенами, просмотр/редактирование текста заметки перед отправкой (опц. режим «модерация»: заметки сначала в черновике, админ одобряет), редактор системного промпта куратора (метод: ABCDX, лестница Ханта, воронка).

### A11. Пользователи и роли `/admin/users`
Список сотрудников (ADMIN/EDITOR), приглашение, смена роли, деактивация. Только ADMIN.

### A12. Настройки `/admin/settings`
Бренд (название, логотип в квадрат-логотипе nav), ссылка на Zoom по умолчанию, тексты писем, версии юридических документов (редактор `LegalDocument`), бот Telegram (статус webhook), провайдер оплаты (статус, тестовый платёж).

## 5. Сквозные UI-элементы

- **Копирование:** компонент `<CopyButton text>` (Clipboard API + fallback), тост «Скопировано», использовать во всех промптах и командах.
- **«Отправить агенту»:** `<SendToAgentButton prompt onSent>`: раскрывает промпт, копирует, отправляет событие `sent_to_agent` (аналитика + `VIEWED`).
- **Плеер:** `<KinescopePlayer id timecodes onProgress>` с Player API, seek по таймкодам, события прогресса (25/50/80/100%).
- **Замок/апгрейд:** `<LockedPanel requiredPlan>`.
- **Тосты, модалки, пустые состояния, skeleton** по разделу 6 `02-design-system.md`.
- **Хлебные крошки:** моно, `Кабинет / Скиллы / SEO-аудит` со стрелкой `solar:alt-arrow-right-linear`.
- **404/403/500:** страницы в стиле рамы (`LinedBlock` с кодом ошибки и кнопкой «На главную»).
- **Доступность:** фокус-кольца (`focus-visible:outline outline-1 outline-[#d95321]`), alt-тексты, клавиатурная навигация в табах/аккордеонах, `aria-live` для тостов, контраст текста ≥ 4.5:1 (`zinc-500` минимально допустим на `#f6f5ef` для 12px+; для мельче использовать `zinc-600`, но лейблы 9–10 px декоративные и дублируются осмысленным текстом).
