# 06. План работ по этапам и критерии приёмки

Сроки и структура соответствуют КП (40–48 календарных дней). Этапы идут последовательно; оплата привязана к приёмке (аванс 30%, Этап 3 30%, финал 40%).

## Порядок работы для Claude Code

1. Прочитать `CLAUDE.md` и `docs/00`–`docs/05`.
2. Перед каждым этапом составить план задач, работать небольшими коммитами.
3. После каждого экрана: сверка с `docs/reference/docuframe-hero.html` и чек-листом из `02-design-system.md` §10.
4. В конце этапа: прогон `lint`, `typecheck`, `test`, `test:e2e`, обновление `README` (запуск, env), демо-сценарий в разделе «Приёмка».

---

## Этап 0. Подготовка (до старта, не входит в 40–48 дней)

Закрыть: платёжный провайдер, домен и бренд. Завести: sandbox-аккаунт провайдера, Kinescope (API-ключ, whitelist домена), SMTP, S3-бакет, VPS в РФ, Telegram-бот, Anthropic API-ключ.

## Этап 1. Каркас: кабинет, роли, оплата, гейтинг (~10–12 дней)

**Задачи**
- Инициализация: Next.js 15 + TS strict, Tailwind с токенами, шрифты, Iconify Solar (офлайн), ESLint/Prettier, Husky, Docker Compose (postgres), CI.
- **Визуальный каркас 1:1 с эталоном:** `AppFrame`, `CornerBrackets`, `Nav`, `TickBorder`, `Crosshair`, `Panel`, `Button` (5 вариантов), `StatusPill`, `LinedBlock`, `Kicker`, `Tag`, формы (Input/Textarea/Select/Checkbox), `Tabs`, `Table`, `Modal`, `Toast`, `useMaskedReveal`. Витрина компонентов `/dev/ui` (только dev).
- Prisma-схема (`03`), миграции, сиды (Plan, admin, editor, демо-студенты).
- Auth: регистрация с согласием ПДн, вход, восстановление пароля, верификация email, rate limits.
- Модели `User`/`Enrollment`/`Payment`/`Plan`; `PaymentProvider` + ЮKassa (sandbox) + `MockProvider`; `/pay`, `/pay/result`, webhook, апгрейд с доплатой разницы.
- **Гейтинг на уровне API:** `assertAccess`, `redactLocked`, middleware редиректов, тесты (`05` §2).
- Онбординг: бизнес-профиль (`/onboarding`), экспорт для агента.
- Роли ADMIN/EDITOR, вход по роли, админ-каркас (меню, обзор, студенты (список/карточка), оплаты, тарифы, пользователи).
- Профиль: вкладки «Профиль», «Бизнес-профиль», «Тариф и оплата», «Приватность».
- Юридические страницы, health-эндпоинт, деплой на staging.

**Приёмка**
- [ ] Регистрация → подтверждение email → выбор SELF → оплата sandbox → webhook активирует Enrollment → онбординг → Главная (каркас).
- [ ] Апгрейд SELF→SUPPORT списывает ровно разницу; после webhook тариф меняется.
- [ ] Повторный webhook не создаёт дублей (тест).
- [ ] Прямой запрос закрытого ресурса без тарифа даёт 402/403, поля контента отсутствуют (тесты из `05` §2 зелёные).
- [ ] ADMIN и EDITOR входят в `/admin`, EDITOR не видит оплат и ПДн.
- [ ] Все экраны этапа проходят чек-лист соответствия эталону; 375/768/1024/1440 без горизонтального скролла.
- [ ] Деплой на staging по HTTPS, `.env.example` и README актуальны.

## Этап 2. Маршрут «агент за 3 дня» + библиотека скиллов (~8–10 дней)

**Задачи**
- `RouteDay`/`RouteStep`/`RouteStepProgress`; экраны S2 (`/route`, `/route/[day]`): чек-лист, копируемые команды/промпты (`CopyButton`), фиксация артефактов.
- `Tag`, `Skill`; экраны S3 (список: группировка, поиск, фильтры по тегам, гейтинг) и S4 (карточка: вход/выход/время/demo, «Отправить агенту», скачивание файла).
- S3/S4 гейтинг: превью для закрытых, presigned URL файлов.
- Прогресс: `Progress` для скиллов, статусы, `SendToAgentButton`.
- Админка: A4 (скиллы), A5 (маршрут), A7 (теги); загрузка файлов в S3.
- Сиды: 3 дня маршрута с шагами, 12 демо-скиллов.

**Приёмка**
- [ ] Студент проходит шаги, отмечает выполнение, вводит артефакт; прогресс сохраняется и отображается на дне и в общем виджете.
- [ ] «Скопировать» работает на десктопе и iOS Safari/Android Chrome.
- [ ] Библиотека сгруппирована по 5 функциям; поиск и фильтры по тегам работают, URL восстанавливает состояние.
- [ ] SELF видит только базовый набор целиком; остальные скиллы как превью с замком; попытка скачать файл закрытого скилла даёт 403.
- [ ] Редактор создаёт/редактирует скилл, меняет теги и `minPlan`; изменение сразу отражается для студентов.
- [ ] Кнопка «Отправить агенту» ставит `VIEWED` один раз.

## Этап 3. Единый контент-движок: Уроки + Юзкейсы + Эфиры (~12–14 дней)

**Задачи**
- Модель `ContentUnit`; компонент `<ContentUnit />` (видео + табы + таймкоды + промпт-блок + KPI + шаги + панель статуса).
- `KinescopePlayer` с seek, `timeupdate`, события прогресса; `Timecodes`, `PromptBlock`, `StepList`, `KpiBlock`.
- Экраны: S5/S6 (уроки, 10 блоков, привязка к маршруту), S7/S8 (юзкейсы, 3 таба, ЦЕЛЬ/РЕЗУЛЬТАТ с KPI, ОПИСАНИЕ со ссылками, «Отправить агенту» + ПРОМПТ + копирование, пошаговые действия с командами), S9/S10 (эфиры, архив).
- Главная: баннеры (A8), лента «Новое», плитка разделов, виджет прогресса + «Движение по деньгам».
- **Единая админ-форма** A6 (уроки, юзкейсы, эфиры), редактор таймкодов, KPI, шагов, TipTap; предпросмотр.
- Гейтинг эфиров («частично» для SELF).
- Сиды: эталонный юзкейс «SEO-движок на агентах» со всеми блоками, 3 урока, 2 эфира.

**Приёмка**
- [ ] Один и тот же `<ContentUnit />` рендерит урок, юзкейс и эфир; в кодовой базе нет дублирующих реализаций.
- [ ] Клик по таймкоду перематывает видео в Kinescope; активный таймкод подсвечивается.
- [ ] Юзкейс содержит все 8 элементов анатомии из ТЗ 5.6; deep-link `?tab=&t=` работает.
- [ ] Редактор создаёт юзкейс, урок и эфир через одну форму; предпросмотр совпадает с публичным видом.
- [ ] Видео и промпты закрытых юнитов не приходят в JSON-ответе для студента без доступа.
- [ ] Просмотр ≥ 80% автоматически ставит `VIEWED`; статусы `SUBMITTED/IMPLEMENTED/RESULT` ставятся вручную с proof.
- [ ] Этап сдан = триггер второго платежа по КП (30%).

## Этап 4. Лидерборд, дашборд админа, Telegram, куратор, адаптив, QA (~10–12 дней)

**Задачи**
- Лидерборд (S11): шкала 1/2/5/10, `LeaderboardEntry`, пересчёт в транзакции + ночной, приватность.
- Дашборд потока A9 (по студентам: посмотрел/сдал/внедрил/результат, фильтры по тарифу, экспорт CSV), A2 карточка с прогрессом.
- Telegram: бот, привязка аккаунта, уведомления, напоминания об эфире; шаги Дня 3 маршрута с инструкцией по выводу агента студента.
- Агент-куратор: джоба `curator.weekly`, S13, `WeeklyReport`, A10, фичефлаг.
- Уведомления S14, настройки A12.
- Мобильная адаптация всех экранов (нижняя навигация на `<md`), доступность, производительность (LCP < 2.5 с на Главной, изображения через `next/image`).
- QA: e2e-сценарии Playwright (регистрация→оплата→онбординг→маршрут→скилл→юзкейс→лидерборд), нагрузочный смоук (100 одновременных пользователей), проверка безопасности (OWASP-чеклист, заголовки), резервное копирование, мониторинг, продакшн-деплой, инструкции по эксплуатации.

**Приёмка**
- [ ] Очки в лидерборде считаются по шкале 1/2/5/10 по максимальному статусу каждого юнита; тесты на расчёт.
- [ ] Админ видит по каждому студенту 4 стадии и результат в деньгах; фильтр по тарифу работает; CSV скачивается.
- [ ] Привязка Telegram и уведомление «разбор готов» доходят; блокировка бота обрабатывается.
- [ ] Куратор в тестовом запуске выдаёт валидный JSON, 1–2 шага со ссылками на реальные сущности, карточка видна студенту SUPPORT+; в промпт не попадают контакты (тест на сборщик промпта).
- [ ] На 375 px все экраны без горизонтального скролла, нижняя навигация работает, тап-таргеты ≥ 40 px.
- [ ] Lighthouse: Performance ≥ 85, Accessibility ≥ 90 на Главной и в юзкейсе (мобильный профиль).
- [ ] e2e зелёные, продакшн развёрнут, бэкапы и алерты настроены, передана документация.
- [ ] Финальная приёмка = триггер третьего платежа (40%).

## Глобальные критерии качества

- TypeScript strict без `any` в доменной логике; общие zod-схемы.
- Покрытие тестами: гейтинг, оплата/webhook, расчёт очков, сборка промпта куратора, права ролей.
- Нет N+1 в списках (Prisma `include`/`select`, индексы из схемы).
- Секреты только через окружение; логи без ПДн.
- Все тексты интерфейса на русском, единый словарь терминов: «Отправить агенту», «Маршрут», «Скиллы», «Юзкейсы», «Эфиры», «Внедрил», «Результат в деньгах».

## Риски и как их снять

| Риск | Митигация |
|---|---|
| Провайдер оплаты не выбран | Абстракция + sandbox ЮKassa; смена адаптера без переделки логики |
| Kinescope Player API ограничения | Прототип seek/timeupdate в первые дни Этапа 3; fallback на iframe без прогресса (ручное «Просмотрел») |
| Точное «1:1» с эталоном при новых экранах | Только токены и паттерны из `02`; чек-лист §10; визуальные снапшоты Playwright ключевых экранов |
| Объём Этапа 3 | Единый `ContentUnit`; TipTap с минимальным набором; переиспользование админ-формы |
| Стоимость LLM куратора | Один вызов на студента в неделю, лимиты токенов, фичефлаг |
| 152-ФЗ | РФ-хостинг, согласия, минимизация данных куратору, процедура удаления |
