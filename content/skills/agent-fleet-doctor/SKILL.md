# Доктор парка агентов

## Когда использовать

Применяй при плановой проверке агентов или сигнале, что один из них не отвечает. Работай только с профилями из утверждённого реестра. Наличие этого скилла само по себе не даёт права менять сервисы.

## Источник истины

Для каждого агента реестр должен задавать профиль, режим gateway, ожидаемый канал, владельца, допустимую команду проверки и разрешение на автоматический перезапуск. Не угадывай имена профилей, служб и команд.

## Порядок работы

1. Поставь блокировку проверки, чтобы два запуска Доктора не восстанавливали один сервис одновременно.
2. Собери только наблюдения: время, `hermes gateway list`, адресный `gateway status --deep`, `hermes -p <profile> doctor`, свежие ошибки и доступные показатели ресурсов.
3. Отнеси агент к одному состоянию: `HEALTHY`, `DEGRADED`, `DOWN`, `STUCK`, `RECOVERING` или `QUARANTINED`.
4. Не считай агента зависшим по одному тайм-ауту. Подтверди сбой второй проверкой после интервала из реестра и исключи плановое обслуживание, перегрузку провайдера и активную долгую задачу.
5. До изменения сохрани диагностический фрагмент без секретов и проверь лимит попыток.
6. Если профиль разрешён, сбой подтверждён и лимит не исчерпан, выполни только адресный штатный `gateway restart` для этого профиля. Не применяй `--all`.
7. После паузы выполни повторный `status --deep`, `doctor` и согласованную функциональную пробу.
8. При успехе зафиксируй восстановление. После двух неудачных перезапусков за 30 минут установи `QUARANTINED`, прекрати изменения и вызови человека.

## Особые режимы

- Если включён Hermes profile multiplexer, проверяй профили раздельно, но перезапускай только основной gateway-мультиплексор.
- Если gateway установлен как системная служба, используй только заранее созданную администратором точечную команду для конкретной службы. Не запрашивай и не используй общий `sudo`.
- Доктор не может надёжно контролировать собственное падение. Его процесс и расписание должен контролировать внешний service manager.

## Запрещено

Не перезагружай VPS, не обновляй Hermes, не удаляй PID/lock/state, не используй `kill -9`, не меняй конфигурацию, права и секреты, не отключай проверки безопасности и не перезапускай все профили разом. Такие действия выполняет администратор по отдельному решению.

## Формат результата

`Время; агент; состояние до; доказательства; действие; номер попытки; состояние после; влияние; следующий шаг; владелец.` Никогда не включай токены, полные переменные окружения, персональные данные и необработанные закрытые логи.

## Критерий завершения

Каждый профиль имеет подтверждённое состояние; выполнено не более одного разрешённого действия за цикл; восстановление проверено функционально либо инцидент остановлен и эскалирован.
